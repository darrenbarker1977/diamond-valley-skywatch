# Camera alignment and sky-map following

Handheld rear-camera preview opens a temporary modal aiming workspace. The live
video, crosshair, selected alignment object, identification checkbox, Record
button, readiness and capture result share the same view. Landscape places video
beside the controls. The record dock can scroll while the video stays in place.

These are the original alignment controls moved into a dock, not duplicated
checkboxes or a second capture path. Opening the camera clears any prior object
confirmation. Record still requires the existing fresh/stable absolute sensor
samples, eligible real object and physical-presence rules. Daylight remains
blocked. Camera imagery is an aiming aid: no object recognition, plate solving,
photo/video recording or uploads are added. One point starts basic guidance;
a second refines it and a third check remains optional.

Close camera and Escape stop tracks, clear the video and restore controls to
Pointing without closing Navigator. Choose a different alignment object closes
the camera and focuses the alignment search. Find my target now uses the existing
Finder navigation, which also stops the preview. Stream loss reports an error and
exits the camera workspace. Mode/site/page visibility changes and late permission
responses retain the existing generation guards and cleanup. Mounted mode keeps
its original top-edge alignment and does not use the camera workspace.

The sky map now exposes Follow aligned phone beside Set up pointing, above the
folded map options. Its visible status distinguishes manual view, aligned/ready,
following, stopped readings, planned skies and unavailable map data. Live time
means astronomical positions update for the selected epoch and location; it does
not mean the map is following the device. The independent compass does not
unlock map-follow or telescope guidance.

A collapsible explanation gives the complete path: after dusk confirm the actual
site, enable pointing sensors, identify and record at least one object, return to
the map and explicitly tap Follow aligned phone. Handheld follows the rear-camera
axis; mounted follows the phone top edge along the tube. Manual panning, centring
and compass-direction controls exit follow. Loss of usable aligned readings also
stops follow; its state explains why and prompts re-enabling once stable. Planned
skies do not follow the phone. No compass values are substituted for aligned pose.

Browser tests use clearly marked local synthetic media and synthetic orientation
only in test code. Physical Pixel 8 camera/sensor accuracy still needs outdoor
verification; this UI change makes no new numerical accuracy claim.
