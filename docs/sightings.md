# Seen it

Tap ✓ Seen it after visually identifying the selected object. A single recorder moves between the finder (including Scope view) and the object details; it never requests sensors or alters alignment. Confirmation records the real device timestamp, observing-site coordinates/name and selected fitted eyepiece setting, if any. The app cannot detect an eyepiece or independently verify an observation or location. Presence confirmation is recorded separately; an unconfirmed selected site is labelled clearly.

Practice and planned skies disable sighting creation and provide Return to real time. Alignment capture, arrow proximity and simply selecting a target never create sightings. Undo removes the exact new record or restores the exact deleted one. The primary button prevents repeated taps for the same object/site/observing night; Log another look deliberately records another visit. Historical values remain unchanged when equipment, site or time settings change.

Things I’ve seen is collapsed in Navigator. Search, per-record details and 20-record pagination keep it compact. Open object browses the current sky without changing the observing location/time or restoring pointing calibration. Home remains a basic launch page. Prefer unrecorded objects affects Show me another and the finder picker, preserves existing ranking within groups, never hides seen favourites and can be switched off.

Data is local to this browser and works offline. It does not sync to ChatGPT or other devices. Download JSON backups before changing devices or clearing browser storage. Restore validates the complete file and merges matching IDs without duplicate observations; malformed files and conflicts change nothing. Exports include coordinates. Unreadable storage is preserved for recovery download; replacing it with a validated backup requires an explicit in-app choice. Storage errors are visible and do not claim a save. Other-tab records are re-read before mutations and storage events refresh the list. Simultaneous browser-tab writes are not a transactional database; use one observing tab and keep backups.

Validation includes storage denial, corrupted data/recovery, bad imports, merge conflicts, repeat observations, Undo, historical snapshots, real versus temporary time, offline reload and seen/unseen suggestions. Browser tests use fixtures; they do not attest actual visual identification or sensor accuracy.

## Weather snapshots

New sightings include an optional immutable Open-Meteo hourly forecast snapshot: cloud cover, Celsius temperature/dew point, km/h wind/gusts, relative humidity and precipitation chance. The app chooses the newest valid forecast already available for the exact selected coordinates and real observation hour. It checks timezone/Alberta clock rules, rejects ambiguous hours, future or over-seven-day cache timestamps and invalid numbers. It never starts a network request or delays a save to obtain weather.

The recording-details disclosure previews available weather. Expanding a saved sighting shows the forecast values, provider, valid hour, download time, age at observation and saved/offline status. Dew risk is a simple forecast temperature/dew-point spread indicator, not a measured condition. Values missing from the source remain absent; unavailable weather does not block the sighting. Old sightings retain their exact records and explicitly say that weather was not recorded. No historical weather is backfilled.

JSON exports now use version 2; version 1 backups still restore. The existing browser storage key is unchanged. Weather is validated, copied and preserved through reload, Undo, export and restore. A legacy record with no weather field remains distinct from a new record explicitly saved with unavailable weather. An older app that cannot read a version 2 backup should be refreshed before restoring it.
