# Temporary-time Navigator practice

Open Navigator → Practise setup with a temporary night sky. Choose a local date and time for the observing location, or Find a dark time, then Start practice walkthrough.

The same guided flow covers phone placement, physical location, fresh absolute sensors, one assumed reference, and optional target selection. Use the phone in hand; leave the telescope parked and covered during daytime practice. Confirm the practice assumption and record while still. Then explore freely or choose a target for moving sky, arrows and optional hot/cold pulses. No star recognition or measured telescope pointing is claimed. Camera aiming is disabled in practice.

Positions, alignment choices, finder destinations and same-eyepiece alternatives use the one frozen temporary astronomy clock. The dark-time shortcut searches 48 hours for solar altitude below −12°, with −6° twilight as fallback; it makes no weather promise. Forecasts, weather and the ordinary phone compass remain real.

Return to real time is available above Navigator and inside the finder. It stops sensors and pulses, discards practice offsets, restores the actual sky and requires a fresh, identified-object alignment after dusk. Changing practice time, location, or leaving Navigator for Home, Forecast, Night Mission or Skywatch also discards the practice session. Reload starts live. Sensor interruption, page hiding, screen rotation and the existing expiry continue to invalidate alignment.

Every setup progress step is a button. Unmet prerequisites route to the earliest required step. Record has a contextual Help me complete this step link; original location/sensor/help controls remain the single owners of their state. Target choice and tours remain optional.

Validation: unit coverage for dark-time selection and polar daylight; browser coverage for daytime practice through real controller alignment/guidance using test-only orientation events, explicit practice labels, pulse requests, clock changes, reload/exit clearing and the ordinary daylight guard. Full existing phone/desktop regression workflow also runs. Browser API acceptance cannot verify physical vibration or accuracy of an actual phone.
